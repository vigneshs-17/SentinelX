### Added

- **Phase 4:** deterministic scenario suite and scorer (`eval/`), `python main.py eval`, CI detection benchmark.
- **Phase 5:** flow extractor, schedule-based labelling, leakage-safe splits, gradient-boosted flow model, HMAC-signed `skops` artifacts with a signed gate file, `docs/DATASET.md`, `docs/ML_FEATURES.md`, generated `docs/ML_REPORT.md` (status: not run).
- **Phase 6a:** sensor/API process split, waitress, sensor heartbeat and health view, retention (`SENTINELX_RETENTION_DAYS`), webhook notifications (generic, Slack, Discord) with dedup, retries and a bounded queue.
- **Phase 6b:** authentication and authorization (Argon2id, server-side sessions, CSRF, roles, API keys, login lockout), `app.db`, append-only audit log, user and API-key CLI.
- **Phase 6c:** `/api/v1` with a single error envelope, rate limiting, trusted-proxy handling, strict security headers, SSE stream cap, OpenAPI 3.1 spec checked against the routes, Dockerfile (separate sensor and API targets), compose file, CI jobs for Schemathesis, ZAP baseline, Trivy, gitleaks and compose integration.
- **Phase 7a-7c:** new console (login, overview, live feed, alert list and drawer with triage, attack graph, sensor health, admin pages, export), no framework and no external origins; 40 browser tests and axe-core checks; screenshots in `docs/img/`.
- **Phase 8:** this documentation set: `README.md`, `docs/DESIGN.md`, `docs/THREAT_MODEL.md`, `docs/OPERATIONS.md` (config table generated by `scripts/gen_config_docs.py` and checked in CI), `docs/WALKTHROUGH.md`, `scripts/gen_readme_results.py`.

### Changed

- Detectors are five event-time classes with bounded, partitioned LRU state; alerts carry an evidence object.
- Alerts are written to `alerts.db` (SQLite WAL, versioned migrations) and `alerts.jsonl` (append-only, rotated); the API reads `alerts.db` read-only.
- Default bind address is `127.0.0.1`; every route is authenticated unless explicitly public.

### Removed

- The single-packet Random Forest model and its pickle files, the SHA-256 "model hash" tooling, and the synthetic dataset generator (D5).
- The multi-worker mode (`--workers`), the combined `python main.py` launcher, and `--mode pcap` options; replaced by subcommands (`sensor`, `api`, `replay`, `run --dev`).
- README claims that were not backed by the code, listed in the Phase 8 step report.

### Audit findings N1-N12 (fixed before 2.0.0)

- **N1** Retention now deletes by `ingested_at` (wall-clock insert time, migration 6), not by packet time, and never runs in `main.py replay`.
- **N2** The API opens `alerts.db` read-only (`mode=ro`, `query_only`) and, on a read-only volume with no `-wal`/`-shm`, falls back to `immutable=1`. `/health` does a real read and returns `degraded` with HTTP 503 on failure.
- **N3** Login lockout is per (client IP, username) pair plus a per-IP counter; the global per-username lock is gone. One warning is logged when `X-Forwarded-For` arrives while `SENTINELX_TRUSTED_PROXIES` is unset.
- **N4/N5** Docs state that the signed gate proves file integrity only. `NET_ADMIN` removed from the compose file and Dockerfile; live capture in a container is untested in CI.
- **N6/N8** Expired sessions and triage rows of removed alerts are deleted every 15 minutes by the API process. Audit retention (`SENTINELX_AUDIT_RETENTION_DAYS`, default 365) runs only through the admin command `python main.py db prune-audit`.
- **N7** `app.db` lock errors are reported as "application database busy", not "sensor database not available".
- **N12** `.schemathesis/` ignored, unreferenced `screenshots/dashboard.png` removed, BOM removed from `LICENSE`, stale comment fixed.
- Four unused settings removed: `SENTINELX_MAX_TRACKED_ENTRIES`, `SENTINELX_MODE`, `SENTINELX_PCAP_PATH`, `SENTINELX_API_DEBUG`.

### After 2.0.0

- **Scan detectors** count a destination only when its handshake did not complete (unanswered, RST-answered or half-open); ordinary browsing to many servers no longer raises `PORT_SCAN` (`detection/handshakes.py`, DESIGN section 10).
- **Breaking API change:** `GET /api/v1/metrics` is now `GET /api/v1/sensor/status` and `GET /api/v1/metrics/history` is now `GET /api/v1/sensor/history` (no alias). Ad blockers block URLs containing "metrics", which blanked the Overview and Sensor health pages.
- The Overview and Sensor health pages now show "Could not load sensor status ..." when a request fails, instead of staying blank.

### Known gaps at this version

- The Phase 5 real-data run (CIC-IDS2017) has not been done, so ML accuracy is unmeasured and ML stays off.
- All CI jobs (regression on Python 3.12 and 3.14, benchmark, fuzz, ZAP, container scans, secret scan, compose, browser) passed on GitHub Actions for commit `cf2a691`. They have not been run against a live capture or a real NIC.
- No screen-reader testing; automated accessibility checks only.
- Live capture inside the Docker container is not tested in CI (CI covers replay, the API and the console).
- The signed ML gate protects against file tampering only; it does not prove the key holder evaluated honestly.
